# Quickstart & Validation: Shrink ext4 Image

## Developer prerequisites

- Everything from feature 001.
- **Docker Desktop**, for generating fixtures and the independent checks only; the product does
  not use it.

## Generate fixtures (once, results are committed)

```powershell
docker run --rm -v "${PWD}/tests/fixtures/ext4:/w/scripts:ro" `
  -v "${PWD}/tests/HddBackup.Core.Tests/Fixtures/ext4:/w/out" `
  debian:bookworm bash /w/scripts/make-fixtures.sh
```

Produces `tests/HddBackup.Core.Tests/Fixtures/ext4/*.img.gz`, `*.manifest.tsv` and
`layout-reference.txt`. Every positive fixture contains hard links, fast and slow symlinks,
device nodes, a FIFO, a sparse file, xattrs/ACL/capability, a 1 500-entry directory, 255-byte
and UTF-8 names, fragmented files and data near the end of the file system:

| Fixture | Content |
|---------|---------|
| `rpi-like-4k.img.gz` | MBR: 64 MiB FAT32 boot + 256 MiB ext4 (RPi OS feature set, 4 KiB blocks) |
| `rpi-like-1k.img.gz` | MBR: 64 MiB FAT32 + 128 MiB ext4 with 1 KiB blocks |
| `rpi-legacy.img.gz` | older Raspbian: no 64bit, no metadata_csum, uninit_bg |
| `rpi-like-gpt.img.gz` | GPT instead of MBR |
| `dirty.img.gz` | ext4 that needs journal recovery (negative) |
| `inline.img.gz` | ext4 with inline_data (negative) |
| `root-not-last.img.gz` | ext4 partition followed by another partition (negative) |

Performance image (not committed, about 3 GiB compressed; SC-004):

```powershell
docker run --rm -v "${PWD}/tests/fixtures/ext4:/w/scripts:ro" -v "E:/hddbackup-perf:/w/out" `
  debian:bookworm bash /w/scripts/make-large.sh
$env:HDDBACKUP_PERF_IMAGE = "E:\hddbackup-perf\large-16g.img.gz"
dotnet test tests/HddBackup.Core.Tests -c Release --filter "FullyQualifiedName~ShrinkPerformanceTests"
```

## Automated tests

```powershell
dotnet test tests/HddBackup.Core.Tests -c Release
```

Must pass:
- crc32c vectors and superblock/descriptor/inode checksum verification on fixtures.
- Reader: lists every file of the fixtures with correct content (SHA-256 manifests generated by
  `make-fixtures.sh` in the container).
- Layout: group/backup/flex_bg geometry matches `dumpe2fs` output recorded for reference sizes.
- Shrink end-to-end on each positive fixture, to the minimum size and to a fixed size: checker
  clean, tree comparison clean, prefix bytes identical, MBR entry updated.
- Negative fixtures: refused with the specific blocker; no output files.
- Cancellation at random points: no output files, source unchanged (hash before/after).

## Independent check (developer, SC-001/SC-002)

```powershell
$env:HDDBACKUP_EXPORT_DIR = "$PWD/out"   # tests copy rebuilt/shrunk images here
dotnet test tests/HddBackup.Core.Tests -c Release
docker run --rm -v "${PWD}:/w" debian:bookworm bash /w/tests/fixtures/ext4/check-output.sh `
  /w/out/shrunk-rpi-like-4k.img /w/tests/HddBackup.Core.Tests/Fixtures/ext4/rpi-like-4k.img.gz
```

Expected: `e2fsck -fn` exits 0 with no messages; the mounted trees (via `debugfs rdump`) are
identical per `diff -r` and per `getfattr -d -m -` / `stat` comparison.

## Manual (real hardware, SC-003/SC-004)

1. Back up a 16 GB Raspberry Pi OS card with HddBackup (USB reader).
2. Restore tab → select the image → insert an 8 GB card → **Write to device…** → offer
   **Shrink and write** → confirm.
3. Time the shrink (≤ 15 min, SSD). The Pi boots from the 8 GB card, logs in, and runs `sudo
   apt update`. On the Pi, `sudo e2fsck -fn` passes with the root FS mounted read-only.
4. Standalone: **Shrink image…** → Smallest possible → the result is at most used +10% / +256 MB.
